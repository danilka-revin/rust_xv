# SketchFlash

Браузерная замена ESP Web Tool: скетч Arduino пишется прямо на странице, собирается **настоящим**
`avr-gcc` + `binutils`, собранными в WebAssembly, и прошивается через Web Serial. Никакого сервера,
никакой установки Arduino IDE, никаких `.bin`, которые надо где-то собирать вручную.

Дизайн — в духе [opencode](https://opencode.ai): почти чёрный холст, тёплый персиковый акцент,
фиолетовый вторичный, тонкие границы и моноширинные детали интерфейса.

## Что умеет

- **Загрузка скетча, а не `.bin`.** Пишете `.ino` (или перетаскиваете файл) — приложение само
  оборачивает его как Arduino IDE: добавляет `#include <Arduino.h>`, генерирует прототипы функций,
  собирает несколько `.ino`-вкладок в один модуль.
- **Компиляция в браузере** для ATmega328P (Arduino Uno / Nano). Работает в Web Worker, поэтому
  редактор не подвисает; ошибки и предупреждения привязываются к строкам скетча, а не к
  сгенерированному файлу.
- **Прошивка AVR** по протоколу STK500v1 (как avrdude): сброс в bootloader, проверка подписи чипа,
  запись постранично и проверка чтением после записи.
- **Прошивка ESP32 / ESP8266** через `esptool-js`: один merged `.bin` (адрес `0x0`) или раздельные
  образы (загрузчик `0x1000`, таблица разделов `0x8000`, приложение `0x10000`), с опцией полного стирания.
- **Монитор порта**: скорость, отправка строк, метки времени, автопрокрутка.
- **Sketch-менеджер**: несколько скетчей и несколько файлов в скетче, примеры, автосохранение в
  `localStorage`, экспорт собранного `.hex`, drag & drop `.ino` / `.hex` / `.bin`.
- Размеры: занятый Flash (точный) и оценка статической RAM.

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:5173
```

`predev` копирует WebAssembly-тулчейн из `node_modules/@horang-corp/avr-gcc-wasm` в `public/avr`
(~55 МБ, в git не попадает). Первая сборка в браузере скачивает `cc1plus.wasm` (~14 МБ) — дальше
он берётся из HTTP-кеша.

```bash
npm run build      # статика в dist/
npm run preview    # проверить сборку локально
npm test           # юнит-проверки + прогон собранного приложения в jsdom
npm run typecheck
```

## Требования

- Chrome или Edge на компьютере (Web Serial нет в Safari, Firefox и на мобильных).
- Плата: Arduino Uno/Nano с bootloader'ом (ATmega328P) для режима AVR, ESP32/ESP8266 для режима ESP.

## Как это устроено

```
src/
  sketch.ts            обёртка .ino → C++ (Arduino.h, прототипы, склейка вкладок)
  hex.ts               Intel HEX ↔ плоский образ флеша
  compiler/
    worker.ts          сборка в Web Worker через avr-gcc-wasm
    index.ts           запрос к воркеру, разбор диагностики, оценка RAM
  serial/
    link.ts            Web Serial: буфер, чтение, DTR, отмена
    stk500.ts          протокол STK500v1 для AVR
    esp.ts             обёртка esptool-js
    uploader.ts        выбор протокола по типу платы
  editor.ts            CodeMirror 6 + тема и подсветка в цветах opencode
  storage.ts           скетчи, примеры, localStorage
  main.ts              состояние приложения и UI
```

### Про ограничения

- AVR-компиляция поддерживает ATmega328P (Uno/Nano) и библиотеки из тулчейна: `Servo`, `Wire`, `SPI`,
  `DHT`, `Adafruit_GFX`/`SSD1306`, `VL53L0X`, `Firmata`, `BMP085`. Остальные библиотеки нужно
  добавлять в сборку тулчейна.
- Компиляции C++ для ESP32 в браузере нет (это отдельный Xtensa-GCC); для ESP приложение работает как
  удобный прошивальщик готовых `.bin`.
- Оценка RAM — эвристика по глобальным буферам скетча, точное значение требует ELF (тулчейн его не отдаёт).
